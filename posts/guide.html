Part 1. 가상환경(venv) 만들고 requirements.txt로 패키지 설치하기

백엔드개발을 위해 작업환경을 설정할 때에 필요한 설정과정

  • venv
  • requirements.txt

flask를 구동하기 위해서는 가상환경을 만들어야한다. 왜일까?

flask는 기본적으로 python 라이브러리이다. python라이브러리들은 서로 의존성도 다르고 버전에 따라 함수나 동작방식이 달라지는 경우가 많다.

따라서 프로젝트 1에서는 flaks 2.x를 쓰다가 프로젝트 2를 위해 flask 3.x를 설치하여 구동하는 순간
프로젝트 1의 flask2.x가 새로 깐 flask3.x로 덮어 씌워지기 때문에 프로젝트1의 코드는 올바르게 작동할 수 없다.

내 컴퓨터의 파이썬 전역환경에 여러프로젝트의 라이브러리가 뒤섞이지 않게 할 방법이 필요했다
=> 그렇게 고안된 방법이 프로젝트 마다 파이썬을 위한 독립적인 공간을 설정하는 가상환경 방식이다.
가상환경 내에 설치된 파이썬 라이브러리들은 내 컴퓨터의 파이썬 전역환경과 독립적으로 작동한다.
현재 프로젝트를 위해 별도 버전의 라이브러리들을 다운받아도 다른 프로젝트들은 전혀 영향을 받지 않는다.

requirements.txt는 왜 필요 할까?

협업을 위해 필요하다. 팀원 6명이 각자 다른시기에 pip install을 하면 설치 시점마다 다른버전의 라이브러리가 깔리게 된다. 어떤팀원의 노트북에선 잘 프로젝트가 잘 돌아가지만 다른 팀원의 노트북에선 돌아가지 않는 불상사가 발생할 수 있다. 따라서 필요한 패키지와 버전을 일괄적으로 적어둔 텍스트 파일 requirements.txt를 팀프로젝트 파일에 공유문서로 넣어 보다 효율적으로 의존성관리를 할 수있다.

1-1. 프로젝트 폴더에서 터미널 열기

VS Code에서 파일 > 폴더 열기로 팀 레포 폴더를 연 뒤 터미널을 연다,
(터미널 경로가 레포 폴더인지 꼭 확인하도록하자) venv는 지금 있는 폴더에 만들어진다.

python --version

Python 3.x.x가 나오면 정상

1-2. 가상환경 만들기

python -m venv venv

앞의 venv는 "venv 모듈을 실행하라"는 뜻이고, 뒤의 venv는 만들 폴더 이름
실행하면 프로젝트 안에 venv 폴더가 생긴다.

1-3. 가상환경 켜기(활성화)

venv\Scripts\activate

터미널 줄 앞에 (venv)가 붙으면 정상

이제부터 pip install은 컴퓨터 전체가 아니라 이 venv 상자 안에 설치된다!

. 터미널을 새로 열 때마다 다시 켜야 하고, 끌 때는 deactivate를 입력한다.

1-4. VS Code에 이 가상환경 알려주기

Ctrl + Shift + P → Python: Select Interpreter → .\venv\Scripts\python.exe를 고릅니다. 이걸 안 하면 터미널에서는 잘 도는데 VS Code가 import flask에 물결선을 치거나, 실행 버튼(▶)이 다른 Python으로 돌아간다.

1-5. requirements.txt로 한 번에 설치하기

레포에 requirements.txt가 있으면 이 한 줄로 끝난다.
해당 파일에 적힌 모든 의존성들이 한 번에 설치된다.

pip install -r requirements.txt

Emade 백엔드에 필요한 패키지는 대략 이렇게 생김.
버전 숫자는 레포에 있는 파일을 따르면 됨

Flask==3.x.x
firebase-admin==6.x.x
python-dotenv==1.x.x

1-6. 패키지를 새로 설치했다면: 목록 업데이트

내가 새 패키지를 설치했다면 팀원들도 알 수 있게 requirements.txt 목록에 반영해줘야함.

pip freeze > requirements.txt

pip freeze는 지금 venv에 설치된 것 전부를 버전과 함께 적어줌.
(그래서 반드시 (venv)가 켜진 상태에서 실행해야 함!! 꺼진 상태에서 치면 컴퓨터 전체에 깔린 엉뚱한 패키지까지 적히게 된다)

이 다음엔 팀원들에게 requirements.txt가 바뀌었으니 pip install -r 다시 해주세요"라고 알려주면 된다.

1-7. venv 폴더는 깃에 올리지 않기

.gitignore에 아래 줄이 있는지 확인하기.

venv/

venv 폴더는 수천 개 파일이고, 안에 내 컴퓨터 경로가 박혀 있어서 다른 컴퓨터에서는 어차피 안 돌아간다.

올릴 것은 requirements.txt뿐이고, 의존성설치는 각자 진행한다.

확인하기

pip list

목록에 Flask, firebase-admin, python-dotenv가 보이면 Part 1 완료

Part 2. Firebase Realtime DB를 만들고 Flask에 연결하기

flask 서버가 firebase DB에 들어가려면 두 가지가 필요하다,

  • 어느 DB? → 주소/database URL
  • 들어갈 자격이 있는지? → 서비스계정 키

이 두가지를 .env라는 이름의 파일에 명시해 적어 둘 것임.

2-1. Firebase 프로젝트 만들기

  1. Firebase 콘솔에 Google 계정으로 로그인
  1. 프로젝트 추가 → 이름 입력(예: emade) → Google 애널리틱스는 꺼도 됨 → 프로젝트 만들기.
  1. 팀원도 콘솔을 봐야 한다면 프로젝트 설정 → 사용자 및 권한에서 팀원 이메일을 추가

2-2. Realtime Database 만들기

  1. 왼쪽 메뉴 빌드 → Realtime Database → 데이터베이스 만들기.
  1. 위치는 싱가포르(asia-southeast1)를 고르기. 한국에서 가장 가까워서 응답이 빠름.
  1. 보안 규칙은 잠금 모드로 시작
  1. 만들어진 화면 위쪽의 주소를 복사해 둔다 ⇒ 이게 databaseURL
https://emade-xxxxx-default-rtdb.asia-southeast1.firebasedatabase.app

잠금 모드 설정하는 이유 ⇒ 잠금 모드는 "브라우저에서 직접 접속하는 사람은 모두 막아라"는 뜻
우리 구조에서는 프론트(React)가 DB에 직접 가지 않고 항상 Flask를 거치고, Flask가 쓰는 firebase_admin은 서비스 계정 키(마스터키)로 들어가서 이 규칙의 영향을 받지 않음. 잠금 모드를 풀어두면 DB 주소를 아는 사람 누구나 주문 데이터를 고치거나 지울 수 있기에 필요한 설정이다.

2-3. 서비스 계정 키(JSON) 받기

  1. 왼쪽 위 톱니바퀴 프로젝트 설정 → 서비스 계정 탭.
  1. 새 비공개 키 생성 → JSON 파일이 다운로드 됨.
  1. 파일 이름을 serviceAccountKey.json으로 바꾸고, 백엔드 폴더(app.py가 있는 곳) 안에 authentication 폴더를 만들어 그 안에 두기

이 파일은 DB를 마음대로 읽고 쓸 수 있는 마스터키임.

팀원에게는 깃이 아니라 카톡, 메일과 같은 개인 채널을 통해 전달해야함. 아니면 팀원이 각자 위 방법으로 새 키를 받게 해도 된다.(키는 여러 개 만들어도 ok).

2-4. .env 파일에 설정 넣기

프로젝트 폴더 맨 위에 .env 파일을 만들고 아래와 같이 적기

SECRET_KEY = "여기에_랜덤_문자열"

FIREBASE_KEY_PATH = authentication/serviceAccountKey.json

FIREBASE_DATABASE_URL = https://emade-xxxxx-default-rtdb.asia-southeast1.firebasedatabase.app
SECRET_KEYFlask가 로그인 세션 쿠키에 위조 방지 도장을 찍을 때 쓰는 비밀값 (Firebase와는 상관없음)python -c "import secrets; print(secrets.token_hex(32))"
명령어로 만든 랜덤문자열을 넣으심 됩니다.
FIREBASE_KEY_PATH서비스 계정 키(마스터키) 파일이 있는 위치authentication/serviceAccountKey.json 백엔드 루트 경로에 authentication 폴더를 만들고 거기에 서비스 키를 넣음.
FIREBASE_DATABASE_URL어느 DB로 갈지(주소)2-2 에서 복사한 그 값

그리고 .gitignore에 두 줄을 추가.

.env
authentication/serviceAccountKey.json

⇒ 왜 코드에 직접쓰지 않고 .env의 변수명으로 해당값에 접근하는가??

코드에 위값들을 하드코딩 해놓으면 깃 허브에서 코드에 접근가능한 불특정다수들이 우리 DB에 접근하는 불상사가 생겨버린다. 위 값들은 관리자 이외에는 접근해서는 안되는 값들이기에 원격 레포지토리에 업로드 되어선 안된다. 따라서 .girignore에 .env를 등록하고 .env와 키파일은 각자의 컴퓨터에만 두어야한다.

2-5. Flask 코드에서 연결하기

Firebase 연결 코드를 firebase.py에 따로 두고, app.py가 시작할 때 한 번 부른다.

firebase.py

import os

import firebase_admin
from firebase_admin import credentials

BASE_DIR = os.path.dirname(os.path.abspath(__file__))

# Firebase Admin 초기화 (앱 시작 시 한 번만)
def init_firebase():
    try:
        firebase_admin.get_app()   # 이미 초기화됐으면 넘어감
        return
    except ValueError:
        pass

    key_path = os.path.join(BASE_DIR, os.getenv("FIREBASE_KEY_PATH"))
    cred = credentials.Certificate(key_path)
    firebase_admin.initialize_app(cred, {
        "databaseURL": os.getenv("FIREBASE_DATABASE_URL"),
    })

app.py

import os
from dotenv import load_dotenv
from flask import Flask
from flask_cors import CORS

from firebase import init_firebase

load_dotenv()      # ① .env를 먼저 읽고
init_firebase()    # ② 그 값으로 Firebase에 연결

app = Flask(__name__)
app.config["SECRET_KEY"] = os.getenv("SECRET_KEY")

CORS(app, supports_credentials=True)

지켜야할 것

  1. 순서 load_dotenv() 다음에 init_firebase() .
  1. 연결은 한 번만
    →     firebase_admin.get_app() 은 이미 연결되 있나를 확인하는 함수
    → initialize_app()을 두 번부르면 안되기 때문
  1. BASE_DIR을 앞에 붙이면 터미널 위치와 상관없이 항상 firebase.py 옆의 authentication 폴더를 찾아줌. 상위경로에서 run flask를 했을 때 키를 못찾는 경우 막기 위함.
  1. CORS(app, supports_credentials=True). React 개발 서버와 Flask(5000번)는 포트가 달라서 브라우저가 다른 사이트로 보고 요청을 막음
    → 이 줄 덕분에 다른 주소에서 오는 요청을 서로 받기도 하고 로그인쿠키도 오가게 될 수 있는 것.

2-6. 연결 테스트하기

연결이 됐는지 확인하는 임시 라우트를 하나 만들기

서버가 켜졌는지는 app.py에 이미 있는 /health로, DB까지 연결됐는지는 아래 임시 라우트로 확인하기 /health는 DB를 건드리지 않아서, 이것만 되고 /db-test가 안 되면 Firebase 설정 문제라고 범위를 좁힐 수 있음!

# app.py에 임시로 추가
from firebase_admin import db

@app.get("/db-test")
def db_test():
    ref = db.reference("connectionTest")
    ref.set({"message": "hello emade"})  # 쓰기
    return ref.get()                      # 읽기
flask run

브라우저에서 http://127.0.0.1:5000/db-test를 열었을 때 두 가지가 모두 보이면 성공

  1. 브라우저에 {"message": "hello emade"}가 나온다 → 읽기 성공
  1. Firebase 콘솔 Realtime Database 화면에 connectionTest 항목이 생겼다 → 쓰기 성공

확인이 끝나면 콘솔에서 connectionTest를 지우고, /db-test 라우트도 커밋 전에 지우자
